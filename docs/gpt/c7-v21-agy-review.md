# C7 經驗池修正規格 v2.1 第二意見審查報告（Antigravity 紙上推演）

- **審查角色**：Antigravity（平衡審查員／第二意見，任務 T2）
- **審查依據**：`PM_STATUS.md`（§0 製作人指令、§2.1 C7 v2.1 定案）、`balance-r5-final-spec.md`、`c7-experience-pool-review.md`、`summary.json`（12 條連續路徑＋r0/r4/r8 MC 抽樣），並交叉核對現有程式碼（`progression.ts`、`growth.ts`、`modes.ts`、`saveStore.ts`、`battleStore.ts`）。
- **核心設計原則檢核**：**好玩第一、爽度第二、英文第三，給玩家「大方」的感覺。**

## 總評：有條件通過（Conditional Pass）——主結構正確，但紙上推演抓出 4 個必敗邊界與程式落差

PM 定案的 C7 v2.1「補齊 8 段跨區銜接（+6,927.5 EXP）＋主線維持 85%（185,640 EXP）＋非主線 15%（32,760 EXP）配追趕衰減」大方向完全正確。然而，直接拿 `summary.json` 的精確經驗帳（誤差 0 EXP）與現有程式碼逐行驗算後，發現**若照 v2.1 字面直接實作，T1 重跑極高機率在 3 個地方撞牆**：

1. **`fast` 路線在 C2 終王前會卡在 `Lv 186～187`（`Δ = -14 ～ -13`），以 1～2 級之差跌破 `fast ≥ 推薦 −12`（`Lv 188`）**——尤其把終王 `recommendedLevel` 從 `199` 修成 `200` 後，門檻實質收緊了 1 級（約 `1,970 EXP`），且答對率高的玩家因為重試少、基礎答題 EXP 反而比 `struggling` 少約 `5,500 EXP`，會出現「`struggling/fast` 過關、`strong/good/average` 反而不及格」的倒掛。
2. **`normal` 路線有兩處未定義落差**：① 現有程式碼 `towerReward`（`src/game/modes.ts:38`）與 `clearTowerFloor`（`src/store/saveStore.ts:1018`）**完全不給 EXP（0 EXP）**；② 若 v2.1 的 `normal` 用「每天 2 次素材本＋每 3 天 1 次塔」**取代**原本 v2.0 的 20 次整圖複習，C2 終王前只會落在 `Lv 189～193`（`Δ = -11 ～ -7`），**跌破 `normal ≥ 推薦 −6`（`Lv 194`）**。
3. **`mastery ≤ 推薦 +15` 存在 Off-by-one 與首通疊加必敗漏洞**：規格寫「超過 +15 級為 0」（`level > rec + 15`），代表在 `rec + 15` 級當下仍拿 `×0.3` 經驗，一跨過 `xpToNext` 就會升上 **`rec + 16`** 直接判定不及格；且即使卡死在 `rec + 15` 停發副本 EXP，下一關主線保底的 **70% 首通池 EXP** 仍會把玩家推上 `rec + 16`。
4. **首領戰第 2、3 次挑戰處於「零新增援助真空帶」**：`battleStore.ts` 中首領戰自第 1 戰起就內建 `blessed = true`，但第 1062 行排除首領戰的 `+20%` 祝福增傷，而 `aidRevive` 要到 `fails >= 3`（**第 4 次挑戰**）才觸發，導致玩家第 2、3 次重打首領**沒有任何額外援助**，與規格 §5、§11.1 衝突。

以下逐題給出**結論、理由、具體數字建議**，最後附**「給 Codex 的實作注意事項」**。

## 1) 追趕機制（推薦 +5 級起 ×0.3、+15 級為 0）會不會讓認真玩的人覺得被懲罰？有沒有更爽又不失控的曲線？

### 結論
**會。直接從 `×1.0` 斷崖砍到 `×0.3`、再到 `×0` 硬歸零，會讓認真做「地圖精通」與每日任務的玩家產生強烈的「防沉迷懲罰感」，違反「大方、爽度第二」原則；且 `+1～+4` 區間語意不明、`+15` 無上限轉金幣／素材有刷資源漏洞。**
建議改為**「落後有追趕紅利（×1.25）＋超前平滑軟衰減（4 段式）＋非主線硬上限預留 2 級首通緩衝（`+13` 封頂）＋溢出一律轉有每日上限的『知識星塵／訓練津貼』」**，並將推薦等級錨點固定在**「玩家當前最前線進度（Frontier）」**而非重刷舊圖的推薦等級。

### 理由
1. **斷崖式砍 70% 收益違反「大方感」，且前期極易誤傷正常學習者**：
   - 在 A1～A2，`xpToNext(lv)` 僅 `150～490 EXP`。從 `summary.json` 可見，`mastery` 玩家為了湊齊第一張地圖的 60 題精通，在 **A1 第 1 張圖（`r0:19`，推薦 Lv7）就已經來到 `Lv 15`（`Δ = +8`）**！玩家明明是在正當完成遊戲鼓勵的「地圖精通」與「守門人詞彙封印」，卻在毫無預警下看到經驗值瞬間只剩 3 折（`-70%`），心理感受不是「系統幫落後者追趕」，而是「系統懲罰我認真背單字」。
2. **規格在 `+1 ～ +5` 之間存在區間歧義，且錨點若綁關卡會懲罰回頭補星／補精通**：
   - PM 規格寫「`≤ 推薦` 全額；超過 `+5` 起 `×0.3`」，中間 **`+1 ～ +5` 級**究竟是 `×1.0` 還是線性遞減並未定義。
   - 若推薦等級看「正在打的那張舊圖」（例如 B1 玩家 `Lv 65` 回 A1 補第 2 張圖的三星或精通，該圖 `rec = 10`），`Δ = +55` 會直接觸發歸零或異常轉換；反之若 B1 玩家卡在第 4 張圖（`rec = 72`）回頭刷第 1 張圖（`rec = 61`），明明落後前線 7 級卻被判 `+4`。因此**追趕倍率必須統一對齊玩家「已解鎖最前線關卡」的推薦等級**。
3. **「+15 為 0 改給金幣／素材」若無每日上限，會變成合法外掛提款機**：
   - 一旦玩家停在 `+15`，所有重刷或掃蕩原本該給的 EXP 若無上限折算成金幣與鍛造素材，玩家就能卡在某區刻意不推主線，無限將 0 成本重刷變成高效率金幣／素材農場，直接衝垮英雄訓練與神聖鍛造經濟。
4. **真正的「大方」是「給落後者加速紅利」，而不是只靠「砍超前者」**：
   - 現制在 `Δ ≤ 0` 只有 `×1.0`，落後 10 級的玩家打素材本並沒有「追趕加速感」。給落後玩家 `×1.25`（顯示「🔥 女神追趕祝福 EXP +25%」），既能讓玩家覺得遊戲很大方，又能自然托住 `fast` 路線不跌破 `-12`。

### 具體數字建議

1. **統一追趕基準等級 `frontierRecLv`**：
   - 取玩家目前已解鎖最高區域 `r = unlockedIndex`、最遠進度 `st = Math.min(bestStage[regionId] ?? 0, regionStageCount(r) - 1)` 的 `recommendedLevel(r, st)`（若該區 20 關地圖皆已打完、準備打區域魔王或守門試煉，即對齊該區上限 `REGION_LEVELS[r][1]`）。
   - 令等級差 $\Delta = \text{player.level} - \text{frontierRecLv}$。
2. **五段式平滑大方曲線（僅套用於非主線 EXP：素材本、時空之塔、掃蕩、錯題修煉、已首通關卡重刷）**：

| 等級差 $\Delta = \text{Lv} - \text{frontierRecLv}$ | 經驗倍率 `xpMult` | UI 呈現文案（正向包裝） | 設計目的 |
|---|---|---|---|
| **$\Delta \le -4$** | **`×1.25`** | 🔥 **追趕祝福 EXP +25%** | 大方托底，讓只打主線＋少量副本的 `fast` 玩家有感升級 |
| **$-3 \le \Delta \le +3$** | **`×1.00`** | 正常全額（不特別跳字） | 舒適主航道，前後 3 級內完全無衰減 |
| **$+4 \le \Delta \le +7$** | **`×0.70`** | ✨ 熟練巡航（EXP 70%＋金幣津貼） | 溫和減速，取代原本 `+5` 直接砍到 `0.3` 的斷崖 |
| **$+8 \le \Delta \le +10$** | **`×0.40`** | ✨ 熟練巡航（EXP 40%＋金幣津貼） | 持續收斂整圖重刷的累積速度 |
| **$+11 \le \Delta \le +12$** | **`×0.20`** | 🛡️ 境界圓滿將近（EXP 20%＋金幣津貼） | 接近區間上限前的最後緩衝 |
| **$\Delta \ge +13$** | **`×0.00`** | 👑 **本區修練圓滿（轉為訓練金幣津貼）** | **預留 2 級給主線 70% 首通池**，保證 `mastery` 絕不超過 `rec + 15` |

3. **折減／溢出 EXP 轉金幣的安全閥（防刷錢漏洞）**：
   - 被追趕曲線扣掉的 EXP（`lostXp = rawXp - acceptedXp`），按 **`8 EXP = 1 Gold`** 轉發「修練津貼金幣」，**不轉發鍛造素材**（避免破壞神聖鍛造稀有度）。
   - 每日透過 EXP 溢出轉換的金幣設硬上限：**`cap = 150 + 50 * unlockedIndex` Gold／遊戲日**（A1 每日最多 +150 金幣、C2 每日最多 +550 金幣），超過後只顯示「今日修練津貼已滿」，徹底杜絕腳本或無限重刷洗錢。

## 2) 驗收門檻（fast ≥ 推薦−12、normal ≥ 推薦−6、mastery ≤ 推薦+15）是否合理？請用 `summary.json` 的數字估算 v2.1 後各路線大概落在哪。

### 結論
**門檻本身的寬度設計（`-12`／`-6`／`+15`）對戰鬥平衡非常合理（每級 `+0.65%` 攻血，`-12` 級僅少約 `5.2%` 面板，靠 Combo 與裝備完全可打）；但以 `summary.json` 精確帳本推算，v2.1 的「副本 EXP 供給量」與「門檻定義細節」有 3 個缺口，導致 `fast`、`normal`、`mastery` 在現有參數下都會出現壓線失敗或必敗邊界。**

### 理由與 `summary.json` → v2.1 精確數值推算

#### A. 基礎經驗帳驗算（與 `summary.json` 核對至個位數）
- 升級公式 `xpToNext(lv) = 100 + 10 * lv`，從 `Lv 5` 升到 `Lv L` 的精確累積經驗為：
  $$\text{TotalXP}(5 \to L) = (L - 5)(120 + 5L)$$
  - `Lv 180` = `178,500`｜`Lv 186` = `190,050`｜`Lv 187` = `192,010`｜**`Lv 188`（`200 - 12` 下限）= `193,980`**
  - `Lv 190` = `197,950`｜`Lv 193` = `203,980`｜**`Lv 194`（`200 - 6` 下限）= `206,010`**｜`Lv 200` = `218,400`。
- **項目 1（跨區 8 段銜接）新增量**：漏算的 `20→21, 40→41, ..., 170→171` 原值共 `8,150 EXP`，乘上主線 85% 後共補入 **`+6,927.5 EXP`**（其中約 `+6,873 EXP` 落在打 C2 最終魔王**之前**，約 `+55 EXP` 落在 C2 終王首通本身）。
- **項目 3（每日素材本 Rush）新增量**：
  - `rushReward` 公式為 `round(correct * 6 * xpScale(r))`（`src/game/modes.ts:25`）。
  - 61 張主線地圖橫跨 9 區的 `xpScale` 加權總和為：
    $$\sum_{r=0}^{8} \text{chapters}(r) \cdot \text{xpScale}(r) = 5(0.56)+5(1.3)+6(1.45)+6(1.95)+7(1.95)+7(2.3)+8(2.7)+8(3.1)+9(3.5) = \mathbf{137.35}$$
  - 換言之，61 天裡「每次素材本平均多答對 1 題」，全期累積就是 **`6 × 137.35 = 824.1 EXP`**。
  - **關鍵分歧點（作答速度假設）**：
    - **保守模擬速度（沿用 `realsim2` 含題型與回饋約 `6.5～7.2 秒/題`）**：60 秒約作答 `8.8` 題 → `strong/good/average/struggling` 每次平均答對約 `8.5 / 7.9 / 7.2 / 6.3` 題，61 次合計僅 **`+7,005 / +6,510 / +5,934 / +5,192 EXP`**。
    - **快節奏快答速度（無戰鬥動畫約 `4.5 秒/題`）**：60 秒約作答 `13.3` 題 → 每次平均答對約 `12.8 / 12.0 / 10.9 / 9.6` 題，61 次合計 **`+10,548 / +9,889 / +8,983 / +7,911 EXP`**。
- **項目 3（英雄時空之塔 Tower）新增量**：
  - 查核 `src/game/modes.ts:38` 與 `src/store/saveStore.ts:1018`：**目前時空之塔首通只給碎片、金幣、徽章，EXP 為 `0`！** 若不補加 EXP，「每 3 天 1 次塔」對等級的貢獻是 **0 EXP**。

#### C. 三個核心發現說明
1. **為什麼 `fast` 的高正確率玩家反而比 `struggling` 低 2～3 級？**
   - 主線 30% 學習池雖有每日知識點補貼上限，但每次答錯多打的題目與戰敗重來仍會領取 `baseAnswerXp`（`3 * xpScale`）。`strong/good/average` 一路順推不重打，拿到的總題數最少，在 C2 終王前比 `struggling` 少拿約 `5,500～5,900 EXP`（約 3 級）。再加上把 C2 終王 `recommendedLevel` 從 `199` 改為 `200`，等於把 `-12` 門檻從 `Lv 187` 拉高到 `Lv 188`，剛好把 `strong/good/average` 卡死在門外或誤差 58 EXP 的刀鋒上。
2. **為什麼 `normal` 必須釐清「20 次地圖複習」去留，且必須給「時空之塔」首通 EXP？**
   - 若 `normal` 取消原本每 3 張圖 1 次的複習、只靠「每天 2 次素材本＋0 EXP 的塔」，61 天下來 `good/average` 最多只到 `Lv 189～193`，絕對過不了 `Lv 194`（`rec - 6`）。
3. **為什麼 `mastery` 字面寫「超過 +15 為 0」一定會在 A1～B2 爆出 `+16`？**
   - 在 A1（`xpToNext ≈ 250～450`），玩家刷精通升到 `frontierRec + 15` 時，若條件寫 `level > rec + 15` 才歸零，在 `rec + 15` 級仍拿 `×0.3` 經驗就會升上 `rec + 16`。即便改成 `level >= rec + 15` 歸零，當玩家帶著 `Lv = rec + 15` 踏入本區最後一關或終王前，主線保底發放的 `firstClear` EXP（不受副本上限限制）仍會再升 1 級變成 `rec + 16`。

### 具體數字建議
1. **驗收門檻維持不變**（`fast ≥ rec − 12`、`normal ≥ rec − 6`、`mastery ≤ rec + 15`，且不連續 3 張地圖低於下限），不放寬標準，改從**補足合理副本收益**讓曲線自然落進甜蜜區：
2. **微調兩項副本基礎經驗，並搭配第 1 題的 `Δ ≤ -4` 追趕 `+25%`**：
   - **每日素材本 `rushReward`（`src/game/modes.ts:25`）**：每答對 1 題的基礎係數由 **`6` 調升為 `8`**（`Math.round(correct * 8 * xpScale(regionIdx))`）。這會讓每次素材本在 8～11 題答對時多給約 `33%` 經驗，61 天下來為 `fast` 穩定補上 **`+2,200～+3,000 EXP`**，使 `strong/good/average` 的 `fast` 路線在兩種速度下都穩穩落在 **`Lv 189～192`（`Δ = -11 ～ -8`）**，不再壓線翻車。

## 3) 吃力玩家 C2 終王首過 60% 是否太低？在不調 BOSS 血量的前提下有什麼援助方案？

### 結論
**60% 首過率「一點都不低」，甚至高於 `balance-r5-final-spec.md` 原訂目標區間，完全不需要調降 BOSS 血量。但程式碼審查發現兩個隱藏問題：① 首領戰在「第 2 次、第 3 次挑戰」存在零援助斷層（玩家連死 3 次感受不到任何系統幫忙）；② C2 最終魔王「沉默君王（全知封印）」要求連對 6 題（72% 玩家達成率僅 `13.9%`）或累積 10 擊才解封隊長技能，造成吃力玩家挫敗感集中在「放不出技能就被磨死」。應把重點放在「修補第 2、3 戰遞進援助」與「戰敗後的互動式熱身增益」。**

### 理由
1. **數據對照規格：首過 60% 已達標，且 v2.1 補齊等級後還會自然上升**：
   - 對照 `balance-r5-final-spec.md` §11.1 驗收表，「吃力玩家（72%）／正常養成」在區域魔王的首過目標原為 **`30%～52%`**（高養成目標為 `55%～80%`）。
   - `summary.json` 中 `struggling/normal` 在 `Lv 191` 時 C2 終王首過率已達 **`60%`（36/60，95% Wilson 信賴區間為 `47.4%～71.4%`）**，大 BOSS 首過率達 **`73%`（22/30）**。
   - 在 v2.1 補入跨區銜接與日常素材本／塔 EXP 後，`struggling/normal` 終王前等級將從 `Lv 191` 升至 **`Lv 197～199`**（主角與英雄可訓練上限同步提高 6～8 級，攻血約再 `+2.5%～+3.5%`），預期首過率會自然微升至 **`63%～68%`**，穩居 PM 設定的 `55%` 門檻之上。
2. **真正的痛點在「重打第 2、3 次沒有變好打」（程式碼實錘 Bug）**：
   - 檢查 `src/store/battleStore.ts:468-470` 與 `:1062`：
     - 一般關卡失敗 1 次有 50% 機率觸發祝福（`BLESSING_DAMAGE = 1.2` 全隊傷害 `+20%`＋答錯保留 70% Combo），失敗 2 次 100% 觸發。
     - **但在首領戰（`bossFight === true`）中**，第 1 戰起 `blessed` 就恆為 `true`，且第 1062 行寫死 `(s.blessed && !s.bossFight ? BLESSING_DAMAGE : 1)`——把 `+20%` 傷害排除了！同時 `AID_REVIVE_AFTER = 3`（要失敗 3 次＝**第 4 次進場**才有復活）、`AID_GUARD_AFTER = 5`（**第 6 次進場**才有減傷）。
     - 結果：**玩家打首領失敗 1 次（第 2 戰）與失敗 2 次（第 3 戰），拿到的數值與第 1 戰 100% 一模一樣，零援助！** 這直接違背 `balance-r5-final-spec.md` §5「失敗兩次以上提供確定援助」與 §11.1「吃力玩家三次內通關率 ≥80%，且失敗援助必須確實生效」。
3. **C2「沉默君王」機制對 72% 正確率玩家的結構性卡點**：
   - 沉默君王一開場就掛上 `seal`（全知封印），鎖住隊長技能；解封條件為 `streak >= 6`（`0.72^6 = 13.9%`）或累計答對 `10` 題（72% 玩家平均要作答 `14` 題、期間挨約 `4` 次反擊＋C2 最快行動條 `×0.65` 的高頻普攻／技能，還伴隨 70% 血量觸發的 `M03 召喚軍團` 答錯額外扣 `6%` 最大生命）。吃力玩家往往在解封前就減員崩盤，體會不到「解封反殺」的爽感。

### 具體數字建議（完全不改 BOSS 血量與基礎攻擊）

1. **填平首領戰第 2、3 次挑戰的「援助真空帶」（修改 `battleStore.ts` 首領援助階梯）**：

| 同關首領累計敗場 `fails` | 挑戰次數 | 建議確定性援助內容（顯示於開場「女神援助」橫幅） | 對勝率與體感的效果 |
|---:|---|---|---|
| `fails = 0` | 第 1 戰 | 維持現狀（魔王祝福：答錯 Combo 保留 70%） | 保留初見挑戰性（吃力玩家首過 ~60–65%） |
| **`fails = 1`** | **第 2 戰** | **開場全隊預充 50% 技能能量＋開場自帶 1 層免費「守護護盾」（擋 1 次答錯不扣血不斷 Combo）** | 解掉前 4 題熱機期的暴斃，第 2 戰勝率拉升至 ~75% |
| **`fails = 2`** | **第 3 戰** | 保留第 2 戰增益＋**提前解鎖「全滅時免費復活 1 次（回復 40% HP，原第 4 戰才給 30%）」** | **確保 3 次內累計通關率突破 90%**，完全對齊規格 §5 與 §11.1 |
| **`fails >= 3`** | 第 4 戰起 | 保留上述增益＋**承受傷害 `-15%`（`fails >= 5` 時 `-25%`）＋全隊思考時間 `+2 秒`** | 保底不卡死任何願意重試的學習者 |

2. **針對「沉默君王（`seal`）」的連敗微調（僅在 `fails >= 2` 生效）**：
   - 首戰完全不動（維持連對 6 題或累計 10 題解封）；當玩家在同一隻沉默君王 **`fails >= 2`（第 3 戰起）**時，將累計答對解封門檻由 **`10` 題降為 `8` 題**（連對 6 題條件不變）。讓 72% 玩家在第 3 戰中段穩定體驗到「🔓 封印解除！下一擊 ×2」的高潮演出。
3. **新增「戰敗熱身（英文換爽度）」可選按鈕（可在 C8/T9 介面實作，不影響純數值模擬）**：
   - 首領戰敗結算畫面提供一顆大方按鈕：**「📖 複習本場答錯的 3 題 → 下一場免費獲得『女神鼓舞（首擊 ×2 ＋ 護盾 1 層）』」**。把「背會剛剛錯的英文」直接變成肉眼可見的破關爽度，完美呼應「好玩第一、爽度第二、英文第三」。

## 4) 你看到的其他風險或漏洞（例如刷副本、經濟、轉職上限吞經驗）

### 風險 A：真人玩家的「轉職等級上限（Lv 40／100／160）永久吞掉主線首通 EXP」致命陷阱

- **結論**：**模擬器不會踩到、但真人玩家一定會踩到的 P0 級永久損檔風險。**
- **理由**：
  - 在 `sim-budget.ts` 中，模擬器一升上 `Lv 30 / 80 / 150` 就會在背景自動呼叫轉職（主職轉職 0 金幣 0 徽章），所以 `c7-experience-pool-review.md` 報告「快速／正常路線沒有轉職上限 EXP 耗損」。
  - **但真實遊戲並不會自動轉職！** 真人玩家必須自己退出關卡、點開「成長」視窗手動選一轉／二轉／覺醒分支。而 `Lv 30 → 上限 40` 只有 10 級緩衝（僅 `3,950 EXP`）、`Lv 150 → 上限 160` 也只有 10 級緩衝（`15,450 EXP`）。
  - 看 `src/game/growth.ts:82`：`if (lv >= cap) cur = 0;`！一旦真人玩家打得正順（或刷了幾場精通）忘記點開選單轉職，升到 `Lv 40 / 100 / 160` 後繼續推主線，**主線 70% 首通池發出的 EXP 會被 `cur = 0` 直接清零銷毀，同時該小關在存檔 v21 被永久標記為「已領取首通」！** 這些主線經驗永遠拿不回來，後續就會硬生生卡在推薦等級以下。此外，若玩家在 `Lv 45` 對唯一轉職過的主職按了 `resetClassPath()`（`saveStore.ts:722`），`bestTier` 退回 `0`（`cap = 40`），在重新點選分支前所有獲得的 EXP 也會被 `lv >= cap` 歸零。
- **具體數字建議**：
  1. 修改 `addXp`（`src/game/growth.ts:75`）：當 `cap < MAX_LEVEL`（亦即卡在未轉職 `40`、一轉 `100`、二轉 `160` 階段，而非 `200` 滿級）時，**不要執行 `cur = 0`**！改為允許 `xp` 暫存累積（上限可設為**「最多暫存 10 級份量的溢滿經驗」**，例如 `bufferCap = 10 * xpToNext(cap)`），並在玩家完成 `advanceClass` 提高 `cap` 的瞬間，自動呼叫一次 `addXp(p.level, p.xp, 0, newCap)` 結算升級、跳出連升慶祝特效！（既保護首通池不蒸發，轉職瞬間連跳好幾級還超級爽！）
  2. 當 `player.level >= ADVANCE_REQ[nextTier]` 且距離 `cap` 剩不到 3 級時，在大地圖與戰鬥結算顯示醒目提示「⚡ 可免費轉職突破等級上限！」。

### 風險 B：「錯題修煉場 → 每日 15 張掃蕩券 → `sweepMap`」無戰鬥秒刷經驗／金幣／首領素材漏洞

- **具體數字建議**：

### 風險 C：英雄訓練金幣 `O(L²)` 二次方膨脹牆 vs `recommendedPower` 戰力顯示失真

- **結論**：**主角能升到 Lv 200，但全期金幣收入只夠把 3 位夥伴英雄練到約 Lv 60～95，導致後期隊友容易倒地掉三星、且 UI「推薦戰力」永遠亮紅黃燈騙玩家。**

## 給 Codex 的實作注意事項

1. **補跨區銜接時，不要直接改動 `REGION_LEVELS[r][0]` 常數！**
   - `src/game/progression.ts:313` 的 `REGION_LEVELS = [[5, 20], [21, 40], ...]` 同時被 `RegionModal` UI 顯示（「推薦等級 Lv 21～40」）、程度測驗 `placementFloor` 與存檔遷移引用。
   - 正確做法：保留 `REGION_LEVELS` 顯示值不變，只在 `experiencePool.ts` 計算第 `r` 區預算時，將起點設為 `const budgetStartLv = r === 0 ? REGION_LEVELS[0][0] : REGION_LEVELS[r - 1][1];`、終點 `const budgetEndLv = REGION_LEVELS[r][1];`，累加 `lv = budgetStartLv` 到 `budgetEndLv - 1` 的 `xpToNext(lv)`。
   - **必寫單元測試斷言**：九區主線 85% 預算未四捨五入前總和精確等於 **`185,640`**（`218,400 × 0.85`），四捨五入後九區首通池＋學習池總和與 `185,640` 誤差 `≤ 9 EXP`。

2. **修 `recommendedLevel` 回傳 `200` 時，注意不要誤動全遊戲 BOSS 血量與攻擊力！**
