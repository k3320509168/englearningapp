## 已重現問題與建議

### P1：世界王在目前本地開發模式跳咒文、重複發獎

位置：`src/components/WorldBossModal.tsx:43`～64；`src/main.tsx` 使用 `StrictMode`。

實際將原元件掛載到 ReactDOM + jsdom，透過開始按鈕、輸入欄與表單提交作答。未替換遊戲答題與發獎邏輯，只有語音 API 改成無聲紀錄器、AudioContext 不提供。測試程式存於證據資料夾。

| 對照條件 | 五次答對後金幣 | 專武券 | 題序 |
|---|---:|---:|---|
| 無 StrictMode | 3,000 | 2 | 1 → 2 → 3 → 4 → 5 |
| 與目前入口相同的 StrictMode | **6,000** | **4** | **1 → 3 → 5 → 7 → 9** |

原因：`setBossHp(prevHp => ...)` 的 updater 裡呼叫其他 setState、store 發獎、音效、celebrate 與 setTimeout。React 開發模式會重複執行 updater 以檢查純度，因此副作用重複。終局畫面仍聲稱獎勵只有 3,000／2，與存檔不符。

修正方向：HP updater 保持純運算；將答題狀態轉移與發獎分開處理，結算具一次性保障，並覆蓋重複 callback、結算後遲到的語音結果。**本輪沒有修正。**

限制：已確認本地開發模式；無 StrictMode 對照沒有重複，不聲稱正式 production build 必然重複發獎。

### P1：平衡報告可在全部模擬失敗時判定全數達標

修正方向：失敗／缺失資料使整次驗收失敗；輸出結構化結果並真正計算門檻；保留各子程序退出碼與原始結果，再重跑驗收。不要只把綠勾換成另一段固定文字。

### P2：世界王示範發音繞過音量設定

位置：`src/components/WorldBossModal.tsx:145`；`src/game/speech.ts:208`。

三個音量欄位 `volume`／`sfxVolume`／`musicVolume` 全設 **0** 後，在實際元件點「聆聽示範」，無聲語音 API 紀錄器仍收到 **volume: 1**。原因是 `speak(text, 0.9)` 沒有傳入發音音量，採預設值 1。

這次測試沒有真的播出聲音。現行設定是三個獨立音量，並沒有一個涵蓋所有聲源的「主音量」欄位。修正時先統一各聲源遵守設定，再評估是否增設一鍵靜音；不要只靜音背景音樂便宣稱所有聲音都已關閉。
