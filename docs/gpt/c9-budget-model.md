# C9 可負擔養成模型：實作前推演（進行中）

目標是查明主線實際收入能買到什麼，再判斷BOSS是否太簡單。不先改BOSS數值。

以下五輪是同一助理切換觀點的設計自審，不是五個獨立模型，也不是五輪題庫審查。

1. **經濟設計者問：怎樣避免材料無限？** 從A1 Lv5、initialSave真實起始券/英雄/零額外材料開始。主線作答/掉落由battleStore發放，轉盤/每日/每週/訓練/召喚/鍛造一律經實際store方法，買不起即停止。主角沒有每圖補到推薦等級，英雄不免費補等級。
2. **模擬審查者問：30次試跑是否變成30次刷金幣？** 先只走一條連續主線資源路徑，在各圖/區域魔王前存快照；驗收每次從同一快照獨立複製，重打只保留該次試跑所得，不把MC重複次數累積到下一張圖。快照包含錯題學習集、遊戲日期與資源紀錄。
3. **玩家研究者問：每日會給多少？** 明示預設一圖一遊戲日（可調maps-per-day），只領真正完成的每日/每週/連續登入獎勵。不補免費素材本/塔/真名/神聖鍛造成功，不模擬無限刷副本。時鐘只在Node模擬程序內改，離開後還原，不更動系統時間。
4. **養成玩家問：誰決定怎麼花？** 先免費本職轉職、花實有券十連抽，從實有英雄選高稀有度且盡量保留僧侶；裝備合法且確有提升才買，普通強化至+3，不免費神聖加護。英雄逐級花金幣升至主角實際等級。所有支出受store合法性/資源檢查，輸出角色/英雄/三欄裝備和來源帳。
5. **平衡審查者問：如果實際等級太低走不到C2？** 必須報告卡在哪裡與哪些快照不存在，不能注入等級/資源穿過去再說C2通過率。這可能表示C7 EXP池需要先解決；C9不得以不完整樣本為據全面加血。區域魔王打倒後假設守門人技能驗證已完成，只開下一區、不送任何資源；試煉成效另由題庫/模式審查驗證。

實作/四玩家模擬/資源對帳仍待完成。原normal/high模型保留作對照，它們不再被描述為可負擔正常玩家。

## 實作驗證中的修正

- `scripts/sim-budget.ts`實際記錄主線、每日、每週、連續登入、轉盤、鍛造/普通強化/升星/英雄訓練，逐筆檢查金幣與每項素材的來源減支出等於餘額。+3不免費給神聖加護。
- 每圖結束先領當日已完成任務，才在下一圖換日，避免把到手獎勵先清掉。相同稀有度優先保留已訓練英雄，訓練輪流各升一級。
- 原腳本一次tick整段作答時間，會遺漏多次敵人出手；現採與useBattleClock相同50ms步進，題目/phase換掉即停止，避免把舊題時間灌給新題。這也代表舊P0模擬和新結果不能直接歸因成「只有養成成本」的差異。
- 原EXP只減xp欄位會在升級後得到負數；現用累積等級需求加當級xp計算真實獲得經驗。金幣分主線毛收入與包含養成支出的淨額。
- 同SEED重跑不一致，查明battleStore的createDecks、shuffleChoice、buildAssist、技能王抽題未沿用setBattleRandom。現統一傳既有random；正式預設仍Math.random，不改數值。新增獨立CLI重跑一致、budget整條A1路徑與經濟JSON一致的測試。**修正前勝率只作診斷線索，不交付作平衡定論。**
- 零樣本不顯示NaN或0%假精確，標明未達/未測。獨立腳本型別檢查也通過，非只依賴src的tsc。

## 模型界線

- 一條準備路徑配多次條件式MC，不等於30條獨立玩家養成路徑；同種子的抽卡/收入僅是一種實現，需多種子敏感度與Claude審查。
- 本策略先買當下可支付且比現裝強的裝備，剩餘金訓練英雄，沒有特意存6000金等UR。未買到某裝備不等於所有正常玩家都買不起；後續可測存錢策略，不能據此認定裝備價格不合理。
- 起點假設PRE完成的Lv5，但不送PRE額外收入；不模擬額外素材本/塔/真名/神聖鍛造/商店永久升級。這是明示的主線＋實領日週任務基準，不是所有副本玩法的上限。
- 作答機率/時間沿用既有profile與題型難度模型，未做實際聽音、辨識等待或長文閱讀的個人速度量測；C5暫停與長文時間仍另處理。勝率是模型結果，不是真人實測。

### 當前決定

- 無證據支持全面加怪物HP。吃力玩家大BOSS/區域魔王在規格40–62%/30–52%範圍；一般玩家大BOSS點估計略高、區域魔王在50–70%範圍。優先保留現有BOSS數值，之後再測個別異常。
- C7仍是重要前提：C2魔王推薦Lv200，本路徑只有142～146，明顯未達全盤規格的等級差要求。先做C4～C7並重跑，不能把當前勝率當v2.0全盤驗收已通過。
- 三次內大BOSS觀察值符合一般≥90%/吃力≥80%的指定要求，但只限本種子/策略/模型；不推成所有玩家保證。
- 沒有在此批調BOSS、英雄或經濟數值。Claude可審查C9實作與結果，再整合下一項。

完整檔案在`docs/gpt/c9-budget-results/`，含四份經濟JSON與四份原始log，manifest記錄Node/TZ/參數與題庫指紋。只保留修正亂數後的verified結果；先前不穩定數字不納入表格。原始log中「技能／圖」舊欄位混入區域魔王樣本，未用於上述判斷；runner已改用mapStats.skills並新增加減FINALS不改每圖技能次數的回歸測試。
