① Combo：資料結構、事件順序與傷害上限
1.1 資料結構【定案】
interface ComboState {
  organic: number;       // 答對與困難題乘法
  skill: number;         // 技能增量，不參與 Bonus 乘法
  trueStreak: number;    // 真實連對，答錯歸零
  skillWindowGain: number;
  answeredInRun: number;
  peak: number;          // 本次冒險最高有效 Combo
}

const effectiveCombo = (s: ComboState) =>
  s.organic + s.skill;


正式程式仍可保留現有 combo 欄位供 UI 使用，但必須由 organic + skill 計算，不應另存一份可能不同步的數字。

const BONUS_CAP = 150_000;

function applyBonus(organic: number, roll: number) {
  const gain = Math.min(
    BONUS_CAP,
    organic * (roll - 1),
  );

  return {
    organic: Math.floor(organic + gain),
    actualGain: Math.floor(gain),
  };
}

1.3 事件執行順序【定案】
// 每 8 次實際作答重設技能 Combo 增量額度。
// 跨小關仍延續同一輪冒險的計數。
function beginAnswer(s: ComboState): void {
  s.answeredInRun++;

  if ((s.answeredInRun - 1) % 8 === 0) {
    s.skillWindowGain = 0;
  }
}

// 技能在合法的施放時點呼叫。
// 不依賴題目是否正確，不追溯修改之前的攻擊。
function grantSkillCombo(
  s: ComboState,
  requested: number,
): void {
  const allowance = Math.max(
    0,
    40 - s.skillWindowGain,
  );

  const gain = Math.min(requested, allowance);

  s.skill += gain;
  s.skillWindowGain += gain;
  s.peak = Math.max(s.peak, effectiveCombo(s));
}

// 答對流程
function onCorrect(
  s: ComboState,
  hardBonusRoll?: number,
): void {
  // 1. 先結算困難題 Bonus
  if (hardBonusRoll !== undefined) {
    const result = applyBonus(
      s.organic,
      hardBonusRoll,
    );
    s.organic = result.organic;
    // UI 顯示 result.actualGain
  }

  // 2. 普通答對 +1
  s.organic += 1;

  // 3. 真實連對 +1
  s.trueStreak += 1;

  // 4. 合法的答對觸發技能增量可在此發放
  //    grantSkillCombo(s, 12 / 20)

  // 5. 計算有效 Combo 與傷害
  const combo = effectiveCombo(s);
  s.peak = Math.max(s.peak, combo);

  // 6. 攻擊敵人、結算傷害與死亡
  // 7. 若所有敵人 HP 歸零，直接結算關卡
}

// 答錯流程
function onWrong(
  s: ComboState,
  hasGuard: boolean,
  hasBlessing: boolean,
): void {
  // 真實連對永遠中斷
  s.trueStreak = 0;

  // 守護最高優先：消耗一次，保留 Combo，
  // 擋下本次答錯傷害及對應負面效果。
  if (hasGuard) {
    consumeGuard();
    return;
  }

  // 祈福與一般衰減互斥，不能疊乘
  const keep = hasBlessing ? 0.70 : 0.50;

  s.organic = Math.floor(s.organic * keep);
  s.skill = Math.floor(s.skill * keep);

  // 然後依現有規則觸發敵人答錯反擊
  triggerWrongAnswerCounterattack();
}

// 換地圖／新冒險
function onNewRun(s: ComboState): void {
  // 同一張地圖 20 小關：不重置
  // 同一場黃金之路／時空之塔：不重置
  // 進入不同地圖或開始新的挑戰：重置
  // 暫停後續玩同一場冒險：保持
  s.organic = 0;
  s.skill = 0;
  s.trueStreak = 0;
  s.skillWindowGain = 0;
  s.answeredInRun = 0;
  s.peak = 0;
}


rally 每次 +12、valor 每次 +20；所有加 Combo 技能共用每八題 +40 上限。

技能增加的 Combo 不能在未來被 Bonus 乘算；技能需要冷卻、能量或其他既有資源時，仍必須符合原本條件。

原本女神祝福、守護技能與被動 guardEvery 的觸發順序，統一在答錯處理流程內完成，不使用事後 setState() 補回 Combo。
1.4 傷害倍率與最終上限【定案公式；需實測驗收傷害】
基礎倍率由下節的錨點對數插值計算。

百萬 Combo 基礎倍率為 ×50；超過百萬後仍緩慢增加，最高到基礎 ×60：
\[
B(C)=\min(60,\ 50+5\log_{10}(C/10^6))
\]

此式只適用於 \(C\ge10^6\)。

保留原本商店比例：
const comboStep = 0.1 + upgrades.combo * 0.02;
const shopScale = comboStep / 0.1;

// baseCurve：錨點插值，百萬後趨向 ×60
const base = baseCurve(effectiveCombo(state));

const comboDamageMultiplier =
  1 + (base - 1) * shopScale;

// 隨實際已購買級數成長的 Combo 倍率上限
const comboMultiplierCap =
  1 + 59 * shopScale;


商店 Combo 升級	100 萬 Combo 時	Combo 最終倍率上限
0 級	×50	×60
5 級	×99	×119
10 級	×148	×178

這個算法限制Combo 來源的傷害倍率，不對裝備、暴擊、屬性剋制直接施加同一個硬上限；實際攻擊仍依現有傷害公式結算。

既有升級照原比例生效，不強行降低已購買級數。對顯示傷害數字可設定合理的縮寫與溢出處理，實際扣血最多扣到剩餘 HP，避免負血量或畫面數字溢位。

⑧ EXP：通關池 70%／學習池 30%【需實測驗收】
8.1 區域總預算
const xpToNext = (lv: number) => 100 + 10 * lv;

function regionXpBudget(
  startLv: number,
  endLv: number,
): number {
  let required = 0;

  for (let lv = startLv; lv < endLv; lv++) {
    required += xpToNext(lv);
  }

  return required * 0.85;
}

const firstClearPool = (budget: number) => budget * 0.70;
const learningPool = (budget: number) => budget * 0.30;


其中 85% 沿用主線提供推薦升級需求約 85% 的既有目標；70／30 則重新分配這部分主線 EXP。

8.3 學習 EXP
保留原本基礎：
const baseAnswerXp = 3 * xpScale(regionIdx);


設定每張地圖精通目標為 \(Q_r\)、該區共有 \(M_r\) 張地圖，依 90% 正確率校準：
\[
XP_{\text{targetAnswer}}
=\frac{0.30E_r}{0.9M_rQ_r}
\]

有效知識點答對的 EXP：
const target = learningPoolXp /
  (0.9 * mapCount * masteryTarget);

const base = 3 * xpScale(regionIdx);

// 總發放量包含原有答對 EXP，不是額外加 target。
const earnedXp = isEligibleKnowledgeSuccess

有效知識點答對指無提示的首次掌握或符合間隔的到期複習；同一知識點當天不重複發放完整知識點補貼。一般重複答對仍可取得原有基礎 EXP，但需監測重刷收益，防止無限制刷低級題成為最佳升級方式。

70／30 是預期玩家的校準比例，不是限制每位玩家只能取得固定 EXP。

8.5 必須執行的連續養成模擬
從失語邊境完成後的 A1 Lv5 開始，連續經過 A1～C2 九區：
- 不在進入新區域時自動注入推薦等級。
- 不重置金幣、裝備、英雄、技能或知識點。
- 保留現有區域解鎖、試煉、援助與轉職規則。
- 分別模擬快速通關、正常冒險、完成地圖精通三種玩法。
- 每 20 小關及每區魔王結束後記錄實際等級、推薦等級、EXP 來源與存檔資源。
